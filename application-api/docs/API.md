# Application API reference (v1.0.0)

Authoritative machine-readable contract: [`openapi.json`](openapi.json) (OpenAPI 3.1, generated by
`cgis-app openapi`). Live: `GET /api/app/openapi.json`, Swagger UI at `/api/app/docs`. Real recorded
request/response pairs: [`examples/`](examples/). All paths below are as seen through the gateway
(`http://localhost:8080`); the service does not strip prefixes.

## 1. Conventions

* JSON in, JSON out (`application/json`), except the multipart upload and file downloads.
* Errors: `{"error": {"code": "<STABLE_CODE>", "message": "<text>", "details": {...}?}}`. Messages never contain
  server paths, SQL, stack traces, passwords or tokens. Request bodies forbid unknown fields (422).
* Pagination: `offset` (≥0) and `limit` (admin ≤200, catalog ≤500) → `{items, total, offset, limit, links.next?}`.
* Times: ISO 8601 with offset. Sizes: bytes. Progress: 0..1, or `null` when indeterminate.
* Credentials are never accepted in the query string (`400 SECRET_IN_URL`).

## 2. Authentication

| Client | How | CSRF |
|---|---|---|
| Browser | `POST /auth/login {username, password}` → `cgis_session` cookie (HttpOnly, SameSite=Strict, Path=/, Secure on HTTPS) + `csrf_token` in the body | send `X-CSRF-Token: <csrf_token>` on POST/PUT/PATCH/DELETE; `Origin`/`Sec-Fetch-Site` must be same-origin |
| Script | `POST /auth/login {…, "token": true}` → `access_token` (same lifetime as a session); `Authorization: Bearer …` | not needed (not ambient) |
| QGIS/GDAL/automation | `POST /auth/tokens {name, expires_in_days≤90, scope: read\|admin}` (needs a password session) → `token` shown once; `Authorization: Bearer <token>` or HTTP Basic with any username and the token as password | not needed |

* `GET /auth/me` is **200 for everyone**: `{"authenticated": false, "user": null, …}` when signed out (with
  `reason: SESSION_EXPIRED|SESSION_REVOKED` and a cleared cookie when a stale cookie was sent).
* Sessions end after `APP_SESSION_TTL_SECONDS` (8 h) or `APP_SESSION_IDLE_SECONDS` (1 h) without requests.
  Logout, password change, role change and disabling an account revoke sessions; revoked/expired credentials
  answer `401 SESSION_REVOKED` / `401 SESSION_EXPIRED`.
* Five failed logins for a username (fifty per client address) within 15 min lock that key for 15 min:
  `429 RATE_LIMITED` with `Retry-After`. Wrong username and wrong password give the same 401 body.
* A `read`-scoped personal access token acts as role `user` even for an admin account; `admin` scope needs an
  admin account. Tokens cannot create tokens or change passwords.

```sh
B=http://localhost:8080
# browser-style session with curl
curl -s -c jar -H 'Content-Type: application/json' -d '{"username":"cgis-admin","password":"…"}' $B/auth/login \
  | tee login.json
CSRF=$(python3 -c 'import json;print(json.load(open("login.json"))["csrf_token"])')
# token for QGIS (read scope)
curl -s -b jar -H "X-CSRF-Token: $CSRF" -H 'Content-Type: application/json' \
  -d '{"name":"QGIS desktop","expires_in_days":30}' $B/auth/tokens
```

## 3. Roles and status codes

| Route family | anonymous | user | admin |
|---|---|---|---|
| `GET /auth/me`, `POST /auth/login`, `GET /api/exports/capabilities`, `/api/app/*` | 200 | 200 | 200 |
| `GET /api/catalog/datasets…` | 200 (only `public` datasets) | 200 (`public`+`users`) | 200 (all) |
| `POST /api/exports`, `GET /api/exports…`, downloads | **401** | 2xx (own jobs) | 2xx (all jobs with `?all=true`) |
| `/admin/*` (every method) | **401** | **403** `FORBIDDEN` | 2xx |
| `/auth/tokens`, `/auth/password` | 401 | 2xx | 2xx |

A dataset the caller may not see answers **404 `DATASET_NOT_FOUND`**, exactly like one that does not exist.
Another user's export job answers 404. Cookie sessions without a valid CSRF header get **403 `CSRF_FAILED`**;
cross-origin requests **403 `ORIGIN_FORBIDDEN`**.

## 4. Admin dataset hosting

Version states (field `status` of each version):

| status | meaning | actions |
|---|---|---|
| `validating` | uploaded; the importer is checking it | — |
| `validated` | importer validation passed | `publish`, `discard` |
| `failed` | validation or publication failed; `validation.errors[]` / `error` give the code | `validate` (retry), `discard`, or upload a corrected file for the same version |
| `publishing` | importer converting to COG / normalizing and registering | — |
| `ready` | published and immutable; the highest ready version is current | — (upload a new version) |
| `staged` | catalog row being imported by another importer run (CLI) | — |

```sh
# 1. upload (multipart: 'metadata' JSON text + 'file'); the file is streamed to server-named staging
curl -s -b jar -H "X-CSRF-Token: $CSRF" $B/admin/datasets/uploads \
  -F 'metadata={"dataset_id":"india-l1-pop-2011","version":2,"title":"India Level 1 population 2011",
       "kind":"raster","product_level":"level1","year":2011,"units":"people_per_cell",
       "source":"CyberGIS Level 1 model run <commit>","provenance":{"license":"CC BY 4.0"}};type=application/json' \
  -F 'file=@india_l1_pop_2011.tif;type=image/tiff'
# -> 202 {"job_id":…,"kind":"upload","status":"queued","links":{"self":"/admin/jobs/<id>"}, …}
curl -s -b jar $B/admin/jobs/<job_id>          # poll: completed = validated, failed = see error.code
# 2. publish
curl -s -b jar -H "X-CSRF-Token: $CSRF" -X POST $B/admin/datasets/india-l1-pop-2011/versions/2/publish
curl -s -b jar $B/admin/jobs/<job_id>          # completed: result.outcome = imported | unchanged
# 3. status of every version
curl -s -b jar $B/admin/datasets/india-l1-pop-2011
```

Upload metadata = the ingestion manifest entry **without `file`** (`dataset_id`, `version` (omit = next free),
`title`, `description`, `kind`, `product_level`, `year`, `units` (required for rasters), `source`, `provenance`,
`checksum_sha256` (optional expected SHA-256), `expect`, `band`, `allow_missing_nodata`, `id_property`,
`name_property`, `level_property`, `unit_id_prefix`). `file`, `asset_path`, `url`, `status` or any unknown key →
`422 INVALID_METADATA`.

| Upload outcome | status | code |
|---|---|---|
| accepted, validation queued | 202 | — |
| identical bytes already ready / already uploaded for this version | 200 | `result.outcome = unchanged / already_uploaded` |
| version ready with different bytes | 409 | `CHECKSUM_CONFLICT` (`details.suggested_version`) |
| version has a different live upload (validating/validated) | 409 | `VERSION_EXISTS` (discard it first) |
| new version of a different kind | 409 | `KIND_CONFLICT` |
| metadata/`kind`/`units` invalid, checksum mismatch | 422 | `INVALID_METADATA`, `CHECKSUM_MISMATCH` |
| not TIFF/BigTIFF or GeoJSON, extension ≠ content, compressed body, nested multipart | 415 | `UNSUPPORTED_MEDIA_TYPE` |
| file above `APP_MAX_UPLOAD_BYTES` (rasters) / `APP_MAX_VECTOR_UPLOAD_BYTES` (GeoJSON) | 413 | `FILE_TOO_LARGE` |
| staging quota / free-space floor | 507 | `STORAGE_FULL` |

Validation/publication failure codes (`job.error.code`, also in the version's `validation.errors[]`) are the importer's
and the pre-checks' codes, upper-cased; the common ones:
`MISSING_CRS`, `UNSUPPORTED_CRS`, `CORRUPT_RASTER`, `MISSING_NODATA`, `INVALID_NODATA`,
`EMPTY_RASTER`, `INVALID_VALUES`, `ROTATED_TRANSFORM`, `EXPECTATION_MISMATCH`, `CORRUPT_VECTOR`, `EMPTY_VECTOR`,
`INVALID_GEOMETRY`, `UNSUPPORTED_GEOMETRY`, `MISSING_UNIT_ID`, `DUPLICATE_UNIT_ID`, `UNIT_ID_CONFLICT`,
`SYNTHETIC_NOT_MARKED`, `CHECKSUM_CONFLICT`, `RASTER_TOO_LARGE`, `TOO_MANY_BANDS`, `SUSPICIOUS_COMPRESSION`,
`COG_CONVERSION_FAILED`, `JOB_ABANDONED`. A failed version never affects the ready versions.

Other admin routes: `POST …/versions/{v}/validate` (re-validate; 409 `INVALID_STATE` / `READY_IMMUTABLE`),
`DELETE …/versions/{v}` (discard an unpublished upload; 204), `PUT /admin/datasets/{id}/access
{"access": "public"|"users"|"admins", "note"}`, `GET /admin/jobs?status=&kind=`, `GET /admin/jobs/{id}`.

## 5. Catalog discovery

`GET /api/catalog/datasets?kind=&product_level=&year=&q=&bbox=minLon,minLat,maxLon,maxLat&offset=&limit=` lists the
current ready version of each permitted dataset with `versions: [{version, status}]`; `GET …/{dataset_id}` and
`GET …/{dataset_id}/versions/{v}` return one. Fields: `dataset_id, version, title, description, kind, product_level,
year, units, crs, bbox (WGS84), resolution_x/y (native CRS units), nodata, width, height, dtype, source, license,
citation, synthetic, group_id, region, checksum_sha256, access, provenance`. Never returned: `asset_path`, any
provenance key or value that looks like a path, URL (except `https://doi.org/…`), credential, host or error trace;
upload user names; URLs in `source` are reduced to their host ("… (link withheld)").

## 6. Exports

`GET /api/exports/capabilities` (public) lists: kinds `full|clip`; raster formats `GTiff`, `COG`; vector `GeoJSON`;
any 2D geographic/projected `EPSG:<code>` as `output_crs`; limits.

```sh
# full native download: completed immediately (201), streamed from the published COG
curl -s -b jar -H "X-CSRF-Token: $CSRF" -H 'Content-Type: application/json' $B/api/exports \
  -d '{"dataset_id":"india-l1-pop-2011","kind":"full","format":"COG"}'
curl -s -b jar -OJ $B/api/exports/<job_id>/download          # Content-Disposition filename, Range supported
# clip, reprojected, asynchronous (202): poll, then download
curl -s -b jar -H "X-CSRF-Token: $CSRF" -H 'Content-Type: application/json' $B/api/exports -d '{
  "dataset_id":"india-l1-pop-2011","version":1,"kind":"clip","format":"GTiff","output_crs":"EPSG:32644",
  "aoi":{"type":"Polygon","coordinates":[[[78.3,17.25],[78.65,17.25],[78.65,17.55],[78.3,17.55],[78.3,17.25]]]},
  "aoi_crs":"EPSG:4326"}'
curl -s -b jar $B/api/exports/<job_id>                      # queued → running (progress) → completed
```

| Request | Behaviour |
|---|---|
| `kind=full`, native CRS (or `output_crs` equal to it), raster `COG` or `GTiff` | **201 completed**: the published lossless COG is streamed unchanged (a COG is a valid GeoTIFF); `ETag`, `Repr-Digest: sha-256=:…:`, `X-Checksum-SHA256`, `Accept-Ranges`, HEAD supported |
| `kind=full`, vector `GeoJSON` in EPSG:4326 | 201: the normalized RFC 7946 GeoJSON asset is streamed |
| `kind=full` with another `output_crs` | 202 job: strip-wise nearest-neighbour warp (bounded memory), tiled DEFLATE GTiff or COG; refused upfront if the grid exceeds `APP_EXPORT_MAX_PIXELS` (413 `OUTPUT_TOO_LARGE`) |
| `kind=clip`, raster | 202 job: pixels whose **centre** lies in the AOI, NoData kept, native grid unless `output_crs` given; 413 `AOI_TOO_LARGE` above `APP_EXPORT_CLIP_MAX_PIXELS` |
| `kind=clip`, vector | 202 job: features intersecting the AOI, geometries cut to the AOI; `NO_FEATURES_SELECTED` if none |

Reprojection copies cell values (nearest neighbour); totals of count rasters are **not** preserved and every
reprojected result carries that warning. Example with real WorldPop 1 km India 2011 data: native total
1 211 157 895, after warping to EPSG:32644 1 194 946 642 (−1.3 %). Use native-CRS exports for analysis.

Job result (`GET /api/exports/{id}` when completed): `filename, format, media_type, size_bytes, sha256, output {crs,
width, height, bounds, transform_gdal, nodata, dtype, units, resampled, resampling, count_valid, sum_valid,
native_count_valid?, pixels_in_aoi?, feature_count?}, provenance {dataset_id, version, title, source, license,
citation, synthetic, checksum_sha256}, warnings[], download_url, metadata_url, expires_at`.
`GET /api/exports/{id}/metadata` returns the same as a JSON attachment.

| Export error | status | code |
|---|---|---|
| not signed in | 401 | `UNAUTHENTICATED` |
| unknown/hidden dataset, unknown version | 404 | `DATASET_NOT_FOUND`, `VERSION_NOT_FOUND` |
| no ready version | 409 | `DATASET_NOT_READY` |
| bad format for the kind / CRS / geometry | 422 | `UNSUPPORTED_FORMAT`, `UNSUPPORTED_CRS`, `INVALID_GEOMETRY`, `UNSUPPORTED_GEOMETRY_TYPE`, `COORDINATES_OUT_OF_RANGE`, `EMPTY_GEOMETRY` |
| AOI rules | 422 / 413 | `AOI_REQUIRED`, `AOI_NOT_ALLOWED`, `AOI_OUTSIDE_DATASET`, `AOI_TOO_LARGE`, `AOI_TOO_COMPLEX` |
| too many running exports per user | 429 | `TOO_MANY_JOBS` (+`Retry-After`) |
| export volume quota | 507 | `STORAGE_FULL` |
| download before completion / after failure or cancel | 409 | `JOB_NOT_COMPLETED`, `JOB_FAILED` |
| download after retention (`APP_EXPORT_TTL_SECONDS`) | 410 | `EXPORT_EXPIRED` |
| cancel a finished job | 409 | `JOB_FINISHED` |
| dataset restricted after the export was made | 403 | `FORBIDDEN` |

Job failure codes inside `error.code`: `OUTPUT_TOO_LARGE`, `JOB_TIMEOUT`, `NO_PIXELS_SELECTED`,
`NO_FEATURES_SELECTED`, `STORAGE_FULL`, `ASSET_UNAVAILABLE`, `DATASET_NOT_READY`, `JOB_ABANDONED`,
`INTERNAL_ERROR`.

## 7. Jobs

`queued → running → completed | failed | cancelled`, and `completed → expired` for exports when the retention
elapses (the file is deleted). `progress` 0..1 with `progress_message`; `attempts` counts tries. A worker that
dies loses its lease (`APP_JOB_LEASE_SECONDS`) and the job is redone from scratch, up to `APP_JOB_MAX_ATTEMPTS`
times, then fails with `JOB_ABANDONED`. On `docker compose stop` a running export is released back to the queue.
Partial outputs are never visible: files are written under temporary names and renamed when complete.
